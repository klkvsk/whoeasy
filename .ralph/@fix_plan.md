## Phase B: Server Registry & Generator

- [ ] B.1 **Fetch whoisserver-world data**: Download current TLD server list from whoisserver-world.com (they provide a downloadable list of TLD → WHOIS server + sample domain). Save raw data to `data/whoisserver-world/`. This data includes sample domains we need for fixture collection later.
- [ ] B.2 **Create TLD registry generator**: Write `generator/GenerateRegistry.php` that reads whoisserver-world data + existing whois CLI tool data (`generator/tld_serv_list`, IP/ASN data files) and produces generated PHP arrays. Output files: `src/Registry/Data/TldServers.php` (TLD → {whois_server, rdap_url, sample_domain}), `src/Registry/Data/Ipv4Ranges.php`, `src/Registry/Data/Ipv6Ranges.php`, `src/Registry/Data/AsnRanges.php`. Each file starts with `// Generated by generator/build.php -- DO NOT EDIT`. Verify: files are generated and loadable.
- [ ] B.3 **Integrate RDAP bootstrap data**: Extend the generator to fetch IANA RDAP bootstrap data (https://data.iana.org/rdap/dns.json, ip.json, asn.json) and resolve.rs data. Merge RDAP URLs into TldServers.php. Verify: TLD entries have RDAP URLs where available.
- [ ] B.4 **Write ServerRegistry class**: Create `src/Registry/ServerRegistry.php` with lookup methods: `resolve(string $query): ServerInfo` that auto-detects QueryType (domain/IPv4/IPv6/ASN) and returns server details. Uses binary search for IP/ASN ranges. Throws `UnsupportedQueryException` for unrecognizable input. Write unit tests in `tests/Unit/Registry/ServerRegistryTest.php`. Verify: tests pass for domain, IPv4, IPv6, ASN, and invalid inputs.
- [ ] B.5 **Run generator and commit**: Run `php generator/build.php` to generate all registry data files. Commit generated files. Verify: all Data/ files exist with populated arrays. `git commit -m "feat(registry): generate server registry from whoisserver-world + IANA data"`

## Phase C: WHOIS Client (New)

- [ ] C.1 **Write new WhoisClient**: Create or rewrite `src/Client/WhoisClient.php` that connects to WHOIS servers via TCP:43 using PHP stream sockets. Must support: configurable timeout (default 30s), optional SOCKS proxy via stream context, referral detection (parse response for "Registrar WHOIS Server:" or similar patterns), returns raw text response. Does NOT depend on v1 adapters. Write unit tests with mocked sockets. Verify: tests pass.
- [ ] C.2 **Commit**: `git commit -m "feat(client): new WhoisClient with TCP:43, proxy, referral detection"`

## Phase D: Universal WHOIS Parser

- [ ] D.1 **Create WhoisParserInterface**: Write `src/Parser/Whois/WhoisParserInterface.php` with method `parse(string $rawResponse, string $serverHostname): StructuredResult`. This is the common interface for both universal and server-specific parsers.
- [ ] D.2 **Write universal WHOIS parser**: Create `src/Parser/Whois/WhoisParser.php` implementing `WhoisParserInterface`. This is the key component replacing 143 Novutec templates. It must: (a) detect key:value patterns in WHOIS text, (b) normalize common field names across servers (e.g., "Domain Name:", "domain:", "domain name:"), (c) extract: domain name, registrar, dates (created/updated/expires), nameservers, status codes, contacts (registrant/admin/tech/abuse with name/org/email/phone/address), (d) handle character encoding via mbstring (best-effort UTF-8 conversion), (e) return partial StructuredResult for partially parseable responses, (f) throw ParseException only for completely unparseable input. Reference the v1 extractors for field name patterns but do NOT reuse v1 code. Verify: can parse a Verisign .com WHOIS response correctly.
- [ ] D.3 **Write parser tests**: Create `tests/Unit/Parser/Whois/WhoisParserTest.php`. Manually create 3-5 sample WHOIS fixture files for known formats (Verisign .com, RIPE IP, ARIN IP, a ccTLD like .de or .uk) in `tests/Fixture/Whois/`. Write tests that parse each and verify key fields are extracted. Verify: tests pass for all manual fixtures.
- [ ] D.4 **Commit**: `git commit -m "feat(parser): universal WHOIS parser replacing 143 Novutec templates"`

## Phase E: Rewire Whoeasy Orchestrator

- [ ] E.1 **Rewrite Whoeasy.php**: Rewrite `src/Whoeasy.php` to use the new components directly (ServerRegistry, WhoisClient, WhoisParser, RdapClient, RdapParser, ResultMerger). Must NOT reference `src/Whois.php` or any v1 code. Implement all query modes: prefer-rdap (try RDAP, fallback WHOIS), prefer-whois (try WHOIS, fallback RDAP), rdap-only, whois-only, both (fetch both, merge). Static factory `Whoeasy::create(?Config)` builds with defaults. Constructor takes all dependencies. Verify: `Whoeasy::create()->query('example.com')` works end-to-end (requires network).
- [ ] E.2 **Write orchestrator tests**: Create `tests/Unit/WhoeasyTest.php` with mocked clients. Test all 5 query modes, fallback behavior, partial failure handling, per-call option overrides. Verify: all tests pass without network I/O.
- [ ] E.3 **Commit**: `git commit -m "feat(orchestrator): rewire Whoeasy to use v2 components directly"`
