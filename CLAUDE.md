# Whoeasy (klkvsk/whoeasy)

Unified WHOIS + RDAP query library for PHP 8.2+. Namespace: `Klkvsk\Whoeasy\`, PSR-4 mapped to `src/`.

## Architecture

### Core Flow

```
Whoeasy::query($input)
  -> ServerRegistry::resolve($input)   // detect query type, find servers
  -> WhoisClient / RdapClient          // fetch raw response(s)
  -> WhoisParser / RdapParser          // parse into StructuredResult
  -> ResultMerger::merge()             // combine if Both mode
  -> QueryResult                       // final output with raw + structured
```

### Key Components

- **Whoeasy** (`src/Whoeasy.php`) — Entry point. Orchestrates query flow with 5 modes: PreferRdap (default), PreferWhois, RdapOnly, WhoisOnly, Both.
- **ServerRegistry** (`src/Registry/`) — O(log n) lookup of WHOIS/RDAP servers from pre-generated PHP arrays. Covers TLDs, IPv4/IPv6 ranges, ASN ranges.
- **WhoisClient** (`src/Client/Whois/`) — TCP:43 socket client with referral chain following, timeout/rate-limit detection.
- **RdapClient** (`src/Client/Rdap/`) — HTTP/HTTPS client (ext-curl). RFC 7480/9083.
- **WhoisParser** (`src/Parser/Whois/`) — Universal key:value parser replacing 100+ legacy templates. Handles all known TLDs via field name normalization.
- **RdapParser** (`src/Client/Rdap/RdapParser.php`) — RFC 9083 JSON parser for domain/IP/ASN objects.
- **ResultMerger** (`src/Result/ResultMerger.php`) — Merges WHOIS + RDAP results. RDAP priority for scalars, combined+deduplicated for arrays.
- **Result model** (`src/Result/`) — readonly value objects: `QueryResult`, `StructuredResult`, `DomainInfo`, `IpInfo`, `AsnInfo`, `Contact`, `Registrar`, `Nameserver`.

### Enums

- `QueryType` — Domain, Ipv4, Ipv6, Asn, NicHandle. Has `guess(string): self` for auto-detection.
- `QueryMode` — PreferRdap, PreferWhois, RdapOnly, WhoisOnly, Both.
- `AuthLevel` — Auth, NonAuth. (Planned for replacement with recursive hops model.)

### Exception Hierarchy

All library exceptions implement `WhoeasyException` (marker interface).

- `ClientException` (base, extends RuntimeException)
  - `ClientRequestException` — carries server/query/rawBody context via fluent `with*()` methods
    - `ClientResponseException` — adds httpCode, PSR response
    - `ClientNetworkException` (implements RetryableException)
      - `ClientConnectException`
      - `ClientTimeoutException`
    - `CurlRequestException` — carries verbose curl log
  - `NotFoundException`
  - `RateLimitException` (implements RetryableException)
  - `NotScrapeableException`
  - `ProxyConnectException`
- `InvalidArgumentException`
- `MissingRequirementsException`
- `ParserException` (`src/Parser/Exception/`)

### Design Decisions

- **Readonly value objects** — All result classes are `readonly class` with typed properties. No setters.
- **Universal parser over templates** — Single WhoisParser handles all servers via field normalization, tested against stored fixtures. No per-server parser classes.
- **Generated registry data** — Server lookup tables are PHP arrays generated at build time from IANA/RIR sources. Opcache-friendly, no runtime network I/O for discovery.
- **RetryableException marker** — Callers can catch `RetryableException` to implement retry logic without knowing specific exception types.
- **Fluent exception context** — `ClientRequestException` uses `->withServer()->withQuery()->withRawBody()` to attach diagnostic info without constructor bloat.

## Workflows

### Build (generate registry data)

```bash
php generator/update-sources.php    # download IANA/RIR source files
php generator/generate-registry.php # generate src/Registry/Data/*.php
```

### Collect fixtures

```bash
php generator/collect-whois-fixtures.php  # fetch WHOIS responses -> tests/Fixture/Whois/
php generator/collect-rdap-fixtures.php   # fetch RDAP responses  -> tests/Fixture/Rdap/
/generate-expected                        # Claude skill: generate .expected.json for new fixtures
```

### Test

```bash
vendor/bin/phpunit              # PHPUnit suite
php bin/whoeasy --help          # verify CLI works
```

Always run `php tests/run-tests.php` after changes. It covers parser fixtures, registry lookups, merger logic, and client detection methods.

Fixtures are stored as raw responses + `.expected.json` sidecar files. Tests parse the raw response and compare against expected output. Expected files are generated by the `/generate-expected` Claude skill (not by a PHP script) — it reads raw WHOIS text and extracts structured data per `RESULT_FORMAT.md`.

## Conventions

- PHP 8.2+ strict_types, readonly classes, backed enums, named arguments
- No docblocks on self-documenting code. PHPDoc only for non-obvious contracts.
- Exceptions carry context (server, query, rawBody) — always attach when available.
- Fixture-based testing: one raw response file + one expected JSON per server/query combination.
